## Vulkan逻辑设备的创建流程（The process of Vulkan logicalDevice）

在上一章节中，我们为Vulkan程序选取了合适的物理设备，但这仅仅是能够使用Vulkan的前置条件。物理设备是Vulkan中的固有设备，想对它进行修改是几乎不可能的，也就是说你的物理设备在计算机运行的时候，它的扩展和特性就已经确定下来了，我们能做的只有根据需求按需添加扩展和特性。图像的绘制和渲染是一个完整的过程，物理设备的扩展和特性选取只是单方面意味着Vulkan支持你后续的某些操作，但执行这些操作的前提是要能够对Vulkan下达指令，让它知道自己可以做什么、应该做什么。此时能够对Vulkan下达指令的地方，就是我们本章节要涉及的内容：**逻辑设备**的创建。

---

### 逻辑设备的创建流程
#### 1.创建头文件契约

首先我们还是先在头文件中声明属性的契约，我们需要在头文件中私有属性类中创建一个`vk::raii::Device`Vulkan设备类型的属性字段`device`，它用来存储物理设备的所有扩展和特性，同样我们还要去私有函数方法区创建一个用于Vulkan逻辑设备搭建的函数。具体的配置如下：

**HelloTriangleApplicatoin.h**

```cpp
class HelloTriangleApplicatoin
```

#### 2.查询逻辑设备特性支持

在这里，我们直接进入到刚才创建的Vulkan逻辑设备搭建的函数的中，进一步定义并实现具体的逻辑设备搭建过程。首先，从Vulkan的官方文档和设计原则来看，我们在搭建逻辑设备正式使用前，必须得优先查询逻辑设备是否支持物理设备的特性，这样做能避免后续所有的验证层逻辑设备兼容的问题。我们参照如下实现：

**HelloTriangleApplicatoin.cpp**

```cpp
void HelloTriangleApplicatoin::CreateLogicalDevice()
{
    //创建Vulkan1.3版本的特性链
    vk::StructureChain<
        vk::PhysicalDeviceFeatures2,
        vk::PhysicalDeviceVulkan13Features,
        vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT
    > featuresChain;

    //引用特性的实例
    auto& baseFeatures = featuresChain.get<vk::PhysicalDeviceFeatures2>();
    auto& vulkan13Features = featuresChain.get<vk::PhysicalDeviceVulkan13Features>();
    auto& dynamicFeatures = featuresChain.get<vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT>();

    //启用特性
    vulkan13Features.dynamicRendering = VK_TRUE;
    vulkan13Features.synchronization2 = VK_TRUE;
    dynamicFeatures.extendedDynamicState = VK_TRUE;
}
```

这部分代码是Vulkan库特有的通用模板容器`StructureChain<>`，你可以称呼它为结构链，主要作用就是把我们显示指定配置的Vulkan结构体用机构体链连接起来，替代整个结构体属性同时指定配置的冗余代码，实现“按需索取”结构体属性的作用，其最终目的就是减少Vulkan代码量，让代码更容易阅读、更容易维护。下面是这段代码的详细解释，仅供参考。

##### 第一步：创建Vulkan特性链

    vk::StructureChain<
        vk::PhysicalDeviceFeatures2,
        vk::PhysicalDeviceVulkan13Features,
        vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT
    > featuresChanin;

- `vk::StructureChain<>`：Vulkan特有的结构体链容器，用于跟据实际需求显示获取属性并配置，同时避免代码冗余精简代码量。
- `vk::PhysicalDeviceFeatures2`：Vulkan物理设备的核心特性，一般在逻辑设备创建时默认启用。
- `vk::PhysicalDeviceVulkan13Features`：Vulkan1.3版本物理设备的新增特性。
- `vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT`：Vulkan动态渲染扩展特性，如果需要在渲染时能够灵活改动渲染管线同时支持延迟渲染、多线程渲染，这是必须需要启用的特性。

##### 第二步：引用特性实例

    auto& baseFeatures = featuresChain.get<vk::PhysicalDeviceFeatures2>();
    auto& vulkan13Features = featuresChain.get<vk::PhysicalDeviceVulkan13Features>();
    auto& dynamicFeatures = featuresChain.get<vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT>();

- `auto& baseFeatures = featuresChain.get<vk::PhysicalDeviceFeatures2>()`：通过结构体链中`vk::PhysicalDeviceFeatures2`创建实例对象的引用。
- `auto& vulkan13Features = featuresChain.get<vk::PhysicalDeviceVulkan13Features>()`：创建Vulkan1.3版本的特性实例对象的引用。
- `auto& dynamicFeatures = featuresChain.get<vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT>()`：创建Vulkan动态渲染特性的实例对象引用。

##### 第四步：配置特性对象属性

    vulkan13Features.dynamicRendering = VK_TRUE
    vulkan13Features.synchronization2 = VK_TRUE
    dynamicFeatures.extendedDynamicState = VK_TRUE

- `vulkan13Features.dynamicRendering = VK_TRUE`：启用Vulkan1.3版本新增的动态渲染特性。
- `vulkan13Features.synchronization2 = VK_TRUE`：启用Vulkan1.3版本新增的同步指令操作特性。
- `dynamicFeatures.extendedDynamicState = VK_TRUE`：启用动态渲染的扩展模块。

#### 3.创建并配置逻辑设备结构体

因为再上一章节中，我们对物理设备的扩展和特性支持都提前查询并配置好了，在这里可以直接对这些受支持的物理设备扩展通过结构体链单独获取属性并显示配置。如果你要开启一项没有提前查询物理设备是否支持的特性，你需要做的就是先查询你的物理设备是否支持该特性，结果显示支持后，你才能到逻辑设备中显示配置这些特性的启用状态，这也是在Vulkan中你获取需求特性的典型步骤。既然我们已经把我们目前需要的特性都提前设置好了，那么就该正式创建逻辑设备结构体并显示配置属性了。首先我们需要先了解这个结构需要的属性参数有哪些，就需要了解结构体的内部构造了，具体如下：

**vk::DeviceQueueCreateInfo**

```cpp
struct DeviceCreateInfo
{
    static const bool allowDuplicate   = false;
    static StructureType structureType = StructureType::eDeviceCreateInfo;

    DeviceCreateFlags             flags_                  = {};  //标志位
    uint32_t                      queueCreateInfoCount_   = {};  //队列族的数量
    const DeviceQueueCreateInfo*  pQueueCreateInfos_      = {};  //队列族信息
    uint32_t                      enabledLayerCount_      = {};  //图层数量
    const char* const*            ppEnabledLayerNames     = {};  //图层名称
    uint32_t                      enabledExtensionCount_  = {};  //扩展数量
    const char* const*            ppEnabledExtensionNames_ = {};  //扩展名称
    const PhysicalDeviceFeatures* pEnabledFeatures_       = {};  //启用特性
    const void*                   pNext_                  = {};
};
```

这是Vulkan逻辑设备结构体创建的属性字段，其中前两个属性我们不必再过多赘述，之前的章节在介绍结构体时已将提及过很多次了，我们只需要关注后面几个属性就够了。

    DeviceCreateFlags             flags_                  = {};  //标志位
    uint32_t                      queueCreateInfoCount_   = {};  //队列族的数量
    const DeviceQueueCreateInfo*  pQueueCreateInfos_      = {};  //队列族信息
    uint32_t                      enabledLayerCount_      = {};  //图层数量
    const char* const*            ppEnabledLayerNames     = {};  //图层名称
    uint32_t                      enabledExtensionCount_  = {};  //扩展数量
    const char* const*            ppEnabledExtensionNames_ = {};  //扩展名称
    const PhysicalDeviceFeatures* pEnabledFeatures_       = {};  //启用特性
    const void*                   pNext_                  = {};

- 核心配置
   - `DeviceCreateFlags flags_ = {}`：设备创建的标志位，在结构体实例化对象的过程时自动填充枚举类型的标志位。
   - `uint32_t queueCreateInfoCount_ = {}`：指定你要创建的队列族的数量（比如图形队列、计算队列、传输队列）。它和下面的 `pQueueCreateInfos_`是配对的。
   - `const DeviceQueueCreateInfo* pQueueCreateInfos_ = {}`：指向一个 DeviceQueueCreateInfo 数组的指针，每个元素描述一个队列族的配置（比如队列族索引、队列数量、优先级）。Vulkan 要求必须至少创建一个队列（通常是图形队列）。

- 层与扩展
   -  `uint32_t enabledLayerCount_ = {}`：Vulkan 1.0 中用于指定要启用的验证层数量，但在 Vulkan 1.0+ 中已经被废弃，现代 Vulkan 用扩展来替代验证层的功能，所以通常设为 0。
   - `const char* const* ppEnabledLayerNames_ = {}`：指向验证层名称数组的指针，同样已废弃，留空即可。
   - `uint32_t enabledExtensionCount_ = {}`：要启用的设备扩展数量。设备扩展是 Vulkan 功能的增量，比如 VK_KHR_swapchain（用于创建交换链）、VK_KHR_dynamic_rendering（动态渲染）等，必须在这里指定才能使用。
   - `const char* const* ppEnabledExtensionNames_ = {}`：指向设备扩展名称数组的指针。比如你要创建窗口渲染的设备，就必须包含 VK_KHR_swapchain 这个扩展名称。
  
- 设备特性与扩展指针
  - `const PhysicalDeviceFeatures* pEnabledFeatures_ = {}`：指向 PhysicalDeviceFeatures 结构体的指针，用来启用物理设备支持的特性，比如几何着色器、 tessellation 着色器、动态渲染等。你需要在物理设备筛选阶段先确认这些特性是否支持，再在这里启用。
  - `const void* pNext_ = {}`：Vulkan 的扩展机制核心，用来链接扩展特性链。比如你要启用 VK_KHR_dynamic_rendering，就需要把对应的 PhysicalDeviceDynamicRenderingFeaturesKHR 结构体通过 pNext_ 挂到这里，告诉驱动要启用这个扩展特性。

---

在了解了逻辑设备结构体中每一个属性的具体含义后，我们就可以正式开始配置我们的结构体了，终于我们的程序也即将把逻辑设备创建完成，真好，我们又向梦中的那个彩色三角形迈进了一步。至于结构体的具体配置，我们展示在这里：

**HelloTriangleApplicatoin.cpp**

```cpp
void HelloTriangleApplicatoin::CreateLogicalDevice()
{
    //上面代码保持不变

    vk::DeviceCreateInfo deviceCreateInfo = {
        deviceCreateInfo.flags                 = {},
        deviceCreateInfo.queueCreateInfoCount  = 0,
        deviceCreateInfo.pQueueCreateInfos     = nullptr,
        deviceCreateInfo.enabledLayerCount     = 0,
        deviceCreateInfo.ppEnabledLayerNames   = nullptr,
        deviceCreateInfo.enabledExtensionCount = static_cast<uint32_t>(requiredDeviceExtension.size()),
        deviceCreateInfo.ppEnabledExtensionNames = requiredDeviceExtension.data(),
        deviceCreateInfo.pEnabledFeatures      = nullptr,
        deviceCreateInfo.pNext                 = featuresChain.get(),
    };
}
```

在我们配置的结构体中，前面的5个属性字段我们暂时让它们处于空的状态，同时由于历史原因我们不再使用`enabledLayerCount`和`ppEnabledLayerNames`两个属性，毕竟Vulkan的最佳实践中已经明确放弃了这两个属性。后面的几个属性我们接下来都会解释到。

    deviceCreateInfo.enabledExtensionCount = static_cast<uint32_t>(requiredDeviceExtension.size()),
    deviceCreateInfo.ppEnabledExtensionNames = requiredDeviceExtension.data(),
    deviceCreateInfo.pEnabledFeatures      = nullptr,
    deviceCreateInfo.pNext                 = featuresChain.get(),

- `enabledExtensionCount`：该属性主要获取扩展层的数量，在之前的章节中我们创建了`requiredDeviceExtension`的扩展容器，这里我们让扩展数量属性等于容器的大小即可。
- `ppEnabledExtensionNames`：该属性原上面的`enabledExtensionCount`属性是强绑定的，该属性需要接收容器中的具体元素，同样这里我们让该属性获取容器的数据即可。
- `pNext`：这个属性是指向下一个结构体的指针，这里直接让他指向这章创建的结构体链的实例对象。

#### 4.存储逻辑设备

**HelloTriangleApplicatoin.cpp**

```cpp
void HelloTriangleApplicatoin::CreateLogicalDevice()
{
    //上面代码保持不变

    device = vk::raii::Device(physicalDevice, deviceCreateInfo);
    if (device == nullptr) {
	    std::cerr << "Vulkan logical device and queue Create failed!";
	    return;
    }
    std::clog << "Vulkan logical device and queue Create success!" << std::endl;
}
```

这里我们将头文件中声明的契约属性`device`存储Vulkan物理设备的创建的逻辑设备实例对象，保证它的生命周期足够的长，确保程序能够长久稳定的运行。同时判断逻辑设备是否创建成功，确保在失败时能够输出提示信息，而不是直接引发程序崩溃。

---

### 创建成功

到这里，我们就完全创建好了一个可以使用的逻辑设备，但是一旦运行程序你或许会发现验证层会输出很多错误提示，不用担心这是正常的错误提示，毕竟我们还没有创建接下来Vulkan需要的结构体，等我们把所有结构体显示配置完成后，终端上只会出现我们自己定义的输出内容。
