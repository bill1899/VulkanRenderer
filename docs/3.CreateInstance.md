## Vulakn实例的创建流程（The process of create Vulkan instance）

上一节中，我们成功创建了GLFW库的窗口，这是很值得让人兴奋的成果，有了它我们就可以渲染出任何我们想要在屏幕上渲染出来的内容，那么接下来我们就直奔这章的主题：去创建Vulkan的实例。

### 创建Vulkan实例
#### 1.创建文件契约签名

为了更好的理解Vulkan渲染过程中整个渲染管线的搭建，我们不妨参照一下第一章节中，绘制的Vulkan程序创建的基本流程图，这对于学习Vulkan这个全手动显示声明和搭建的图形库和API来说无疑是锦上添花帮助，这会让我们有一个宏观全局的视角来精确定位我们当前在Vulkan程序构建的阶段和环节。你可以简单的把Vulkan设计的程序作为一个工厂，这样会加深你对Vulkan图形库，甚至同级别同类型的库，例如DirectX 12库和metal库的理解，这三个本质上都是基于图形学理论的不同实现方式，底层的数学原理和计算机科学原理是通用的，这也意味着你学习完Vulkan后，再去了解Window专属的现代图形库DirectX 12和MacOS专属的现代图形库Metal，会更加容易也会对他们的实现原理更加通透。

上面也说到了把Vulkan的构建过程想象成工厂运行生产商品的过程，是非常合适且高度抽象易于理解原理工作，因为相比于理解“怎么做”知道“为什么这么做”会更加利于大脑对Vulkan的学习。那么本章创建Vulakn实例的的过程，你可以理解为 ==“为工厂注册产品生产经营许可的营业执照”== 的过程。

- ##### 实例创建的流程
  >- ###### 第一步注册属性结构体字段
  >- ###### 第二步选择Vulkan的扩展层支持
  >- ###### 第三步完全组装成Vulkan实例对象

在大致了解Vulkan实例对象创建的流程后，我们就可以开始着手准备了，我们首先完成第一步的内容，在 `HelloTriangleApplication` 类中的私有属性里注册字段。

**HelloTriangleApplication.h**

```cpp
class HelloTriangleApplication
{
private:
    GLFWwindow*                        window        = nullptr;         //窗口实例
    vk::raii::Context                  context;                         //Vulkan上下文
    vk::raii::Instance                 instance      = nullptr;         //Vulakn实例对象

public:
    void run();

private:
    void initVulkan();
    void mainLoop();
    void cleanUp();
    void initWindow();

    void CreateInstance();
}
```

在上面代码中我们在 `HelloTriangleApplication` 类中添加了 `vk::raii::Context` 结构体类型的实例对象 `context` 字段和 `vk::raii::Context` 结构体类型的实例对象 `instance` 字段以及`CreateInstance()`的函数方法，前两个是构建Vulkan应用程序必不可少的一环，这也和传统的OpenGL图形库类似，需要创建上下文来记录图像绘制的命令，从而最终在Drawcall指令调用时能够正确读取绘制的步骤命令让图像成功渲染到窗口界面。当然为了便于理解更容易一点，用上面我们提到的营业执照来比喻的话，`instance` 对象可以想象成营业执照本身，而 `context` 对象可以想象成营业执照上记载的内容，它约定了你工厂的名称、地址、社会统一信用代码、负责人以及经营范围等内容，也就是说如果有关部门要来查检你的工厂，只需要看一下你的营业执照就对工厂有了大致的了解。后面的函数方法是主要选择扩展和组装Vulkan实例的地方。这里需要注意的是Vulkan是允许创建多个 `context` 和 `instance` 对象的，但在本项目中是不需要的。

#### 2.创建项目信息

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateInstance()
{
    //创建应用程序信息
    constexpr vk::ApplicationInfo appInfo(
        "Hello Triangle",              //项目名称
        VK_MAKE_VERSION(1, 0, 0);      //项目的版本
        "Cloud Engine",                //引擎名称
        vk_MAKE_VERSION(1, 0, 0),      //引擎版本
        vk::ApiVersion14               //Vulkan版本
    );
}
```

在这里我们创建了 `vk::Application` 结构体，并通过Vulkan-hpp的官方C++封装版本，使用该结构体的构造函数创建出了 `appInfo` 实例对象，该结构体内部存在5个属性字段，其完整结构如下：

**vk::Application**

```cpp
struct ApplicationInfo 
{
    static const bool allowDuplicate = false;
    static StructureType structureType = StructureType::eApplicationInfo;

    const char* pApplicationName_;
    uint32_t    applicationVersion_;
    const char* pEngineName_;
    uint32_t    engineVersion_;
    uint32_t    apiVersion_;
    const void* pNext_;
}
```
在这个结构体中我们将重点关注后面6个参数，因为这是Vulkan要求你必要显示手动传入的，否则该结构的创建会失败，而前面2个参数基本是绝大多数Vulkan结构体都有的，Vulkan-hpp库将这两个属性封装了默认的值，也就是说你可以自由决定是否显示手动传参给它们使用，但都不会造成程序崩溃和报错。那么该结构中这些参数的具体功能展示在下方：

> bool allowDuplication   //是否允许覆盖先前内容
> StructureType structureType //该结构在C风格结构体中对应的结构体

这两个属性中 `allowDuplication` 是一个 `bool` 类型的属性，是说明是否允许覆盖结构体的内容，假设你之前已经设置了该结构体的内容，如果该属性值为 `true` 或者为 `VK_TRUE`，那么你后面再次使用该结构体中的属性并重新设置值的话，Vulkan会允许该操作通过，否则就会禁止该操作，这时你只能通过备选方案调用该结构体中的相关属性 `set` 函数方法来实现相同的效果。而 `StructureType` 是一个 `StrutureType` 枚举类型的属性，我们之前提及过该项目是用Vulkan-hpp的C++封装库来实现的，而Vulkan本身是一个原生C语言库，这意味着要从之前C语言类型的普通属性改变为C++类型的结构体成员属性，需要通过建立映射关系才能让属性变化成功，而使用枚举类来实现映射操作是非常适合的，所以你才会看到这个属性已经被赋值为`StructureType::eApplicationInfo`，这本质上就是该C++类型的结构体在C语言中对应的结构体名称上具有差异而已。

> const char* pApplicationName_    //应用程序的名称
> uint32_t    applicationVersion_  //应用程序的版本
> const char* pEngineName_         //引擎的名称
> uint32_t    engineVersion_       //引擎的版本
> uint32_t    apiVersion_          //Vulkan库版本
> const void* pNext_               //结构链

上面这6个属性是 `ApplicationInfo` 这个结构体必须要显示手动传入的属性字段，第一个 `pApplicationName_` 属性用于指定应用程序的名称，也就是项目的名称，它接收一个 `const char*` 的字符串类型的常量指针作为参数，这里我们给项目取名为 `Hello Triangle`；第二个属性 `applicationVersion` 用于指定项目的版本信息，它接收一个32位整型变量作为位参数，我们这里用 `VK_MAKE_VERSION(1, 0, 0)` 宏作为参数传入，括号中的数字分别表示 `major`主要版本、`minor`次要版本以及`patch` 链接版本；第三个属性 `pEngineName_` 也是`const char*` 类型的属性，用于指定Vulkan引擎名称，我们这里取名为 `Cloud Shadw`; 第四个属性 `engineVersion_` 用于指定Vulkan引擎的版本，我们给他指定为 `VK_MAKE_VERSION(1, 0, 0)`；第五个参数 `apiVersion` 用于指定当前Vulkan使用的版本，这里我们用Vulkan提供的编译期全局常量 `vk::ApiVersion14` 来显示指定我们用到的是Vulkan1.4版本库；最后一个属性 `pNext` 主要用Vulkan的结构链，它主要用于把指定的结构体实例相互连接起来，便于内存的访问和读取。

#### 3.构建项目实例对象

创建完完整的项目信息后，我们就可以进入下一步阶段，开始正式创建Vulkan实例对象，我相信这是很简单的一步，这个过程就跟游戏中满级大佬选择装备一般，Vulkan本身就是天花板级别的现代图形库，它要求的显示配置结构体操作就和装备选择差不了多少。一样的，我们先来看看Vulkan实例结构体是什么样子的构造吧。

**vk::InstanceCreateInfo**

```cpp
struct InstanceCreateInfo
{
    static const bool allowDuplicate = false;
    static StructureType structureType = StructureType::eInstanceCreateInfo;

    InstanceCreateFlags            flags_;
    const ApplicationInfo*         pApplicationInfo_;
    uint32_t                       enabledLayerCount_;
    const char* const*             ppEnabledLayerNames_;
    uint32_t                       enabledExtensionCount_;
    const char* const*            ppEnabledExtensionNames_;
    const void*                    pNext_;
}
```

前两个属性我们上一节就已经讲过了，因此在这里我们就不在过多的赘述了，直接进入后面属性来解释它们的作用。

> InstanceCreateFlags flags;

这个属性在Vulkan中以CreateInfo为尾缀的结构体中十分常见，它的作用是指定位掩码，来确定该结构体的具体类型和作用，防止功能混淆和崩坏。


> const ApplicationInfo* pApplication_;

这个属性是一个指针，它的具体类型是`ApplicationInfo`，也就是我们第二步中显示构建的ApplicationInfo结构体。


> uint32_t enabledLayerCount_;
> const char* const* ppEnableLayerNames_;

这两个属性是要求Vulkan是否启用多图层属性，它们接收的是`uint32_t`类型的值和`const char* const*`类型的指针，主要用来启用Vulkan验证层。但是现代Vulkan最佳实践要求，尽量减少`enabledLayerCount_`的使用，因为Vulkan的结构特性链就已经有很强大的扩展功能了，没有必要在多此一举为验证层单独设立扩展的方式，同时不同平台和设备的扩展名称和支持性不同，这不仅会让Vulkan扩展管理变得更加混乱，还会让Vulkan的跨平台能力大打折扣。


> uint32_t enabledExtensionCount_;
> const char* const* enbledExtensionNames_;

这两个属性是要求Vulkan是否启用设备支持的扩展属性，其中`enabledExtensionCount`是支持扩展属性的数量，而`enabledExtensionName_`则是支持扩展属性的具体名称，通过搭配合适的扩展属性，就能让Vulakn在不同的设备和平台间进行渲染，这也是Vulkan跨平台性和灵活性的能力根源。

---
 
现在我们已经大致了解了`InstanceCreateInfo`这个结构体内部所有属性的真正用途，那么现在就该来正式配置这个结构体的属性了。具体配置如下：

**vk::InstanceCreateInfo**

```cpp
vk::InstanceCreateInfo instanceCreateInfo = {
    instanceCreateInfo.flags                  = {},        //标志位
    instanceCreateInfo.pApplication           = &appInfo,  //应用程序实例
    instanceCreateInfo.enabledLayerCount      = 0,         //验证层
    instanceCreateInfo.ppEnabledLayerNames    = nullptr,   //验证层名称
    instanceCreateInfo.enabledExtensionCount  = 0,         //扩展层
    instanceCreateInfo.ppEnabledExtensionNames = nullptr,  //扩展曾名称
    instanceCreateInfo.pNext                  = nullptr    //结构体链链接对象
}
```

我们这里对以上结构体内容的配置进行解释，这里我们使用了C++17标准特性中的结构体来联合初始化，对于`flags`属性我们直接选择填入空实现，你完全不用担心程序会崩溃，因为Vulkan-hpp库已经为这个属性赋予了一个初始化值了，我们完全没有必要再去多次一举了；`pApplication`属性接收的类型就是我们之前手动配置的`ApplicationInfo`结构体的实例对象，不过需要注意的是这里是使用指针来接受的对象，我们需要对对象使用`&`取址符来告诉指针指向的具体对象的地址；后面的`enabledLayerCount`和`enabledLayerNames`这两个关于验证层的启用，我们先设为不启用，因为本章的主题是创建Vulkan实例对象，启用验证层需要额外的操作来实现，如果在这里阐述就显得有点超纲了；同样`enabledExtensionCount`和`ppEnabledExtensionNames`这两个属性是关于启用Vulkan扩展层开关，要是这里展开来讲也显得有些复杂，所以这两个属性我们目前也设置为不启用；那么最后一个`pNext`属性也没必要过多说明它的作用，之前我们就已经说明了它的用法，只不过目前我们还暂且用不到它。

#### 4.组合Vulkan实例对象

**HelloTriangleApplication**

```cpp
instance = vk::raii::Instance(context, instanceCreateInfo);
if(instance == nullptr) {
    std::cerr << "Vulkan instance Create failed!" << std::endl;
    return;
}
std::clog << "Vulkan instance Create success!" << std::endl;
```

最后当我们通过`InstanceCreateInfo`结构体将内部的所有必要属性填充完毕后，我们就可以执行本章节的最后一步操作，也就是将真正的Vulkan实例组装起来。还记得我们之前为了便于理解Vulkan构建流程时，抽象出来得现实世界中得例子吗？在这里我们使用到它。在这里我们使用Vulkan-hpp的C++封装中的`vk::raii::Instance`类来组装成真正得Vulkan实例对象，我们直接调用它得静态类成员构造函数，它需要一个`vk::raii::Context`和一个`vk::raii::InstanceCreateInfo`对象作为参数来创建具体实例，这就相当于我们在一张纸上写入工厂的各种具体信息，那么一份完整的工厂营业执照不就出来了吗。但在这里我们也必须防止中途会产生的各种以外情况，因而我们使用条件判断来测试Vulkan实例对象是否真的组装成功了，如果没有它也不会莫名其妙没有错误提示的崩溃掉，这一点在以后我们调试时用于定位问题非常有用。
