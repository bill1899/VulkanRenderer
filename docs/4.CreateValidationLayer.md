## Vulkan验证层的创建流程（The process of create Vulkan validationLayer）

上一节中，我们深入探讨了如何在Vulkan中创建实例，并且亲自动手把Vulkan实例的创建流程实现了一遍，这样做很不错，毫无疑问动手操作是学习任何知识时效率最高的方式之一。但即便如此，我们也不能小瞧Vulkan的门槛，作为当前最高效的图形库和API之一，它的难度可以说是最高的那一档，当然我们也不是说让大家放弃Vulkan，相信都听过风险越大回报越多这句话吧，你不妨想象一下你掌握Vulkan图形库的时候，任何出现在你面前的关于图形编程和图形学的问题都将迎刃而解。所以当前阶段讲太多都是意义不大的，那么就赶紧开始我们创建Vulkan验证层的工作吧。

### 验证层的创建流程
#### 1.创建文件契约签名

由于Vulkan自身的特性，它无法直接将错误信息直接打印输出到终端当中，这也就造成了一个常见的现象，只要运行Vulkan应用程序很多时候会出现渲染场景漆黑一片或则窗口界面在桌面上一闪而过，这是正常情况并不是Vulkan库本身的问题，这是因为Vulkan设计之初就是为了极致性能考虑的，而在运行时使用Vulkan验证层会使Vulkan程序的性能大打折扣，这不是我们期望的结果，所以如果要解决这个问题你只需在Vulkan程序当中显示实现验证层就可以了，当然我们期望在调试期间开启验证层，让更多的错误信息提前暴露出来逐个解决，倘若验证层不在输出错误日志并且你认为程序也已经准备完成后，你完全可以禁用Vulkan验证层来进一步提高程序的性能。

**HelloTriangleApplication.h**

```cpp
constexpr uint32_t SCR_WIDTH = 1280;
constexpr uint32_t SCR_HEIGHT = 800;

//添加验证层
const std::vector<const char*> validationLayers = {
    "VK_LAYER_KHRONOS_validation"
};

//定义验证层的开关
#ifdef NDEBUG
constexpr bool enableValidationLayers = false;
#else
constexpr bool enableValidationLayers = true;
#endif //NDEBUG
```

在上面这段代码中，我们首先定义了全局常量`validationLayers`它是`std::vector<const char*>`类型的值，并且把它的初始值设置为`"VK_LAYER_KHRONOS_validation"`这个值是Vulkan提供的扩展属性宏，原本是可以直接使用这个宏来导入验证层扩展的，但是由于我们使用的是Vulkan-hpp的C++封装版本，因此我们需要用把这个宏用双引号设置为字符串形式来导入验证层。接着我们用预处理指令定义一个验证层启用规则的开关，我们创建了名为`enableValidationLayers`的`bool`类型的编译期常量，并将启用规则设置为是否在`NDEBUG`的调试环境下，如果是在调试环境下程序就会启用验证层，否则就会关闭验证层以提高性能。

光是这样还不够，Vulkan的验证层同样需要一个实例对象来接收存储它，这时我们就需要在头文件的私有属性字段中声明验证层的实例属性字段了。就像这样：

**HelloTriangelApplciation.h**

```cpp
class HelloTriangleApplication
{
private:
    GLFWwindow*                        window        = nullptr;         //窗口实例

    vk::raii::DebugUtilsMessagerEXT    debugMessager = nullptr;         //Vulkan验证层

private:

    void mainLoop();

    static VKAPI_ATTP vk::Bool32 VKAPI_CALL debugCallback(
        vk::DebugUtilsMessageSeverityFlagsEXT severity,

```

我们在`HelloTriangleApplication`类的私有属性中新添加了`debugMessager`属性字段，并且在私有方法中新添加了`setupDebugMessager()`和`debugCallback`函数方法，到这里，本章节需要在头文件中添加和修改的操作就已经完全搞定了，接下来的任务就是在源文件中如何具体定义Vulkan验证层的扩展实现了。

---

#### 2.构建验证层扩展

在这一步操作流程中，我需要创建一个完全对我们开发Vulkan程序有用的验证层，它必须具备将程序开发过程当中产生的任何问题打印输出到终端的能力，这是对于验证层我们所能期望的最低要求，否则也没有必要开启验证层降低程序的性能。下面就展示如何开启验证层：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateInstance()
{
    //上面代码保持不变

    //创建验证层容器，并把验证层扩展插入容器中
    std::vector<const char*> requiredLayers;
    if(enableValidationLayers) {
        requiredLayers.assign(validationLayers.begin(), validationLayers.end());
    }

    auto layerProperties = context.enumerateInstanceLayerProperties(); //列举Vulkan实例支持的扩展属性
    for(const auto& requiredLayer : requiredLayers) {
        if(std::ranges::none_of(layerProperties, 
            [requiredLayer](const auto& layerProperty){
                return strcmp(layerProperty.layerName, requiredLayer) == 0;
            }
            )
        )
        {
            throw runtime_error("Required layer not supported: " + std::string(requiredLayer));
        }
    }
}
```

在上面的代码中，我们先创建了`requiredLayers`这个临时局部容器，并判断我们是否启用了Vulkan验证层的开关，如果启用了验证层，我们就把验证层扩展的专属容器`validationLayers`整个插入到临时容器中。接下来我们使用`context.enumerateInstanceLayerProperties()`列举出整个Vulkan实例支持的所有扩展属性，并用`layerProperties`临时容器存储支持的扩展属性。紧接着用C++20的`ranges`范围库来逐一遍历`requiredLayers`容器和`layerProperties`容器，查找比较`layerPropertes`中是否有扩展名称和`requiredLayers`相同的扩展，如果没有就抛出运行错误：不支持该扩展。

---

我们已经创建好了Vulkan验证层的基本骨架，就等着填充完整的调试打印输出信息了，这时我们就该用到提前在头文件中声明契约的`setupDebugMessager()`函数方法了。它的内容如下：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::setupDebugMessager()
{
    //验证是否启用了验证层
    if(!enableValiadationLayers) {
        return;
    }

    //设置严重性等级
    vk::DebugUtilsMessageSeverityFlagsEXT severityFlags(
        vk::DebugUtilsMessageSeverityFlagsEXT::eVerbose |
        vk::DebugUtilsMessageSeverityFlagsEXT::eWarning |
        vk::DebugUtilsMessageSeverityFlagsEXT::eError
    );
    //设置消息类型
    vk::DebugUtilsMessageTypeFlagsEXT messageTypeFlags(
        vk::DebugUtilsMessageTypeFlagsEXT::eGeneral |
        vk::DebugUtilsMessageTypeFlagsEXT::ePerformance |
        vk::DebugUtilsMessageTypeFlagsEXT::eValidation
    );
}
```

这段代码就是完整的创建Vulkan验证层的过程，最开始我们先检查验证是否启用了验证层，如果没有启用验证层我们就直接退出函数，接着我们分别设置验证层打印输出信息的严重等级和信息类型，这里涉及到了一个Vulkan的通用结构类型`vk::Flags<>`，它主要是为了Vulkan中大量的枚举类型设计的特殊结构，这里我们使用它来设置我们的信息严重等级和类型的枚举值。

| 枚举值       | 严重等级 |  处理优先级           |
|-------------|----------|----------------------|
| `eInfomation`|  常规    | 正常日志输出，无需处理也不会影响程序 |
| `eVerbose`  |  详细    | 推荐问题处理，建议处理可能会影响程序 |
| `eWarning`  |  警告    | 需要问题处理，推荐处理可能让程序崩溃 |
| `eError`    |  错误    | 强制问题处理，必须处理否则程序崩溃   |

如上图所示，这是`vk::DebugUtilsMessageSeverityFlagsExt`枚举类中信息的四个等级划分，在这个项目中我们将把信息的严重等级设置为`eVerbose`建议、`eWarning`警告、`eError`错误三个等级，便于我们在调试程序时能够直接明了的发现问题原因，杜绝任何影响程序性能和稳定性的因素。

| 枚举值                   | 信息类型     |
|-------------------------|--------------|
| `eDeviceAddressBinding` |  设备绑定信息 | 
| `eGeneral`              |  创建信息    | 
| `ePerformance`          |  性能信息    | 
| `eValidation`           |  验证信息    | 

上面这个表格是`vk::DebugUtilsMessageTypeFlagsEXT`枚举类中信息类型的划分，在这个项目中我们只选择`eGeneral`、`ePerformance`、`eValidation`这三个枚举值作为打印输出到终端的信息。到这里我们已将把Vulkan验证层的消息打印输出等级和类型都给设置好了，下面我们将要创建并配置验证层的主要结构体属性。

---

在正式创建并配置验证层时，我们需要先了解验证层结构体的内部属性参数，毕竟验证层也属于Vulkan的一部份，这样做有利于我们对整个Vulkan知识有更深刻的了解，同时也有利于我们在大脑中构建完整的Vulkan知识网络。

**vk::DebugUtilsMessengerCreateInfoEXT**

```cpp
struct DebugUtilsMessengerCreateInfoEXT
{
    static const bool allowDiplicate = false;
    static Structuretype structureType = Structuretype::eDebugUtilsMessengerCreateInfoEXT;

    DebugUtilsMessengerCreateFlagsEXT  flags_;
    DebugUtilsMessagerSeverityFlagsEXT messageSeverity_;
    DebugUtilsMessagerTypeFlagsEXT     messageType_;
    PFN_DebugUtilsMessengerCallbackEXT pfnUserCallback_;
    void*                              pUserData_;
    const void*                        pNext_;
}
```

这个结构体的整体属性结构和之前我们见过的结构体有着极为相似性，由于前两个属性已经在之前的结构体配置时，见过很多次面了这里就不再过多赘述了，我们直接跳入后面几个属性字段的讨论中。`flags_`属性我们也见过多次面了，它是用于决定这个结构体的具体功能的关键属性；`messageSeverity_`属性就是先前我们已经配置过的`severityFlags`局部变量，大家也都应该知道它是用来决定信息打印等级的属性；`messageType_`属性我们也在之前配置完成了，它负责将验证层的不同信息类型都能够打印输出到终端；至于`pfnUserCallback`属性就是定义一个消息打印的回调函数，它就是将消息打印输出的具体执行函数，只要满足消息等级或者消息类型中的任意一个条件，它都会被调用执行；`pUserData`属性表示是否使用使用者的信息。

---

由于Vulkan验证层的创建结构体需要传入一个回调函数来实现程序运行时能够将信息输出到终端的的执行方法，我们必须在创建配置`DebugUtilsMessengerCreateInfoEXT`结构体前，创建一个回调函数来正确执行信息的打印输出，好消息是，我们在之前的头文件契约声明时已经提前创建好了回调函数，那么这里就是使用它的时候了，所以让我们来实现这个回调函数的内容。

**HelloTriangleApplication.cpp**

```cpp
VKAPT_ATTP vk::Bool32 VKAPI_CALL HelloTriangleApplication::debugCallback(
    vk::DebugUtilsMessageSeverityFlagsEXT severity,
    vk::DebugUtilsMessageTypeFlagBitsEXT type,
    const vk::DebugUtilsMessengerCallbackDataEXT* callbackData,
    void* pUserData
)
{
    std::cerr << "[" << vk::to_string(severity) << "] " 
    << "[" << vk::to_string(type) << "] "
	<< CallbackData->pMessage << std::endl;

    if(severity.operator&(vk::DebugUtilsMessageSeverityFlagBitsEXT::eError) != vk::DebugUtilsMessageSeverityFlagsEXT{} ||
    severity.operator&(vk::DebugUtilsMessageSeverityFlagBitsEXT::eWarning) != vk::DebugUtilsMessageSeverityFlagsEXT{})
    {
        	std::cerr << "validation layer: type" << to_string(type) << " msg: " << CallbackData->pMessage << std::endl;
    }
    return vk::False;
}
```

在回调函数中，我们将消息的等级、类型和回调的具体内容以及自定义的信息作为参数传入，首先把所有的调式信息通过标准错误流输出到终端界面，包括：信息等级、信息类型以及具体的消息内容。然后我们把信息等级为`eError`和`eWarning`两个等级的消息通过回调函数重点打印出来，最后我们把返回值设置为`vk::False`，这样回调函数打印的信息就不会突然中断，而是能够持续不断地打印出来。当然在这里我们并没有使用到我们自己自定义的消息，这在目前阶段是没有必要的，现阶段的Vulkan调试信息就已经足够使用了。

---

终于到了激动人心的时刻，我们执行Vulkan验证层配置最为关键的一步，我们会在这里创建并搭建出完整的验证层，这是我们必须做的事情，它会在以后我们分析调试Vulkan程序是大显神通。具体配置如下：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::setupDebugMessager()
{
    //上面的代码保持不变

    //创建调试检索信息的结构体
    vk::DebugUtilsMessengerCreateInfoEXT debugUtilsMessagerCreateInfoEXT(
        debugUtilsMessagerCreateInfoEXT.flags = {},                       //标志位
        debugUtilsMessagerCreateInfoEXT.messageSeverity = severityFlags,  //调试消息的严重等级
        debugUtilsMessagerCreateInfoEXT.messageType = messageTypeFlags,   //调试消息的消息类型
        debugUtilsMessagerCreateInfoEXT.pfnUserCallback = vk::PFN_DebugUtilsMessengerCallbackEXT(debugCallback), //信息回调函数
        debugUtilsMessagerCreateInfoEXT.pUserData = nullptr,              //是否使用用户信息
        debugUtilsMessagerCreateInfoEXT.pNext = nullptr,
    );
}
```

在这里，我们同样默认`flags`属性为空实现，把这个任务交给编译器帮我们解决；把先前创建好的`severityFlags`和`meaagerTypeFlags`两个局部变量以及`debugCallback`函数方法，作为消息等级和消息属性以及具体消息内容的最终值，至于其他的属性，由于我们目前阶段没有使用到，所以我们暂且设置为空指针备用。

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::setupDebugMessager()
{
    debugMessager = instance.createDebugUtilsMessagerEXT(debugUtilsMessagerCreateInfoEXT);
    if(debugMessager == nullptr) {
        std::cerr << "Vulkan debugMessage Create failed!" << std::endl;
		return;
    }
    std::clog << "Vulkan debugMessage Create success!" << std::endl;
}
```

这里我们将之前的在头文件中声明的`debugMessager`属性字段作为，验证层的具体载体对象，让它保存验证层的具体信息，同时我们还将在上一届创建的实例对象中添加验证层的扩展，让Vulkan验证层能够真正意义上为我们所使用。具体情况如下展示：

**HelloTriangleApplication.cpp**

```cpp
vk::InstanceCreateInfo instanceCreateInfo = {
    instanceCreateInfo.flags                  = {},        //标志位
    instanceCreateInfo.pApplication           = &appInfo,  //应用程序实例

}
```

这里我们替换了`enabldedLayerCount`属性和`ppEnabledLayerNames`属性的值，由于我们已经将Vulkan验证层创建并配置完成了，那么我们就可以理所应当的启用验证层来Vulkan开发之旅启用一层保险设施。
