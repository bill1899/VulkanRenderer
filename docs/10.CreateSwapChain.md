## Vulkan交换链的创建流程（The porcess of Vulkan swapChain）

上一节中，我们详细讲解了如何创建Vulkan渲染界面，渲染界面的成功创建，意味着后续Vulkan的渲染结果可以通过窗口界面可视化输出到屏幕，这对结果的准确性提供了保障。接下来，本章节的核心内容是讲解如何创建Vulkan的交换链，这也是非常重要的一环，理解起来相对于前面的章节，Vulkan交换链的创建是比较抽象且新颖的概念，所以总体的概念和创建流程会比较困难和繁琐，但是也不必过于担心忧虑，按照本章内容来逐步学习理解，我相信Vulkan交换链的知识也应该是非常容易的内容。

### 交换链的创建流程
#### 1.创建头文件契约

按照C++的最佳实践，我们首先要做的仍然是到头文件中私有属性创建Vulkan交换链需要使用的属性字段实例对象，同时，还必须创建几个函数方法签名，这是Vulkan交换链的创建的核心方法，它们需要创建在头文件的私有函数方法区域就行。综合来看具体的创建内容如下展示：

**HelloTriangleApplication.h**


在项目的头文件中，私有属性区域的属性字段实例对象新创建了三个属性字段，分别为：

- `vk::raii::SwapchainKHR swapChain = nullptr`：这是Vulkan中创建交换链的核心类，这里是Vulkan-hpp的C++封装简化版本。
- `vk::SurfaceFormatKHR swapChainSurfaceFormat`：这是Vulkan中用于适配渲染界面和交换链大小的类，这里也是Vulkan-hpp的C++简化封装版本。
- `vk::Extent2D swapChainExtent;`：这是Vulkan中创建交换链大小的类，用于指定交换链的宽度和高度，同样这里也是Vulkan-hpp的C++简化封装版本。

这里我们创建了5个新的函数方法，这些函数全是Vulkan交换链创建过程中必须显示指定的核心方法，接下来我们将一一解释：

- `static uint32_t chooseSwapMinImageCount(const vk::SurfaceCapabilitiesKHR& surfaceCapabilities)`：这个静态方法主要用来创建交换链的渲染帧数，类似于OpenGL中的双缓冲机制。
- `static vk::SurfaceFormatKHR chooseSwapSurfaceFormat(const std::vector<vk::SurfaceFormatKHR>& availableFormats)`：这段代码的作用是从设备支持的格式列表中，为Vulkan交换链选择一个合适的颜色格式与颜色空间组合，这是保证渲染画面正确显示的关键步骤。
- `static vk::PresentModeKHR chooseSwapPresentMode(const std::vector<vk::PresentModeKHR>& availablePresentModes)`：这段代码的作用是为 Vulkan 交换链选择最佳的图像呈现模式（Present Mode），它直接决定了渲染好的图像如何被送到显示器显示，对画面的流畅度和延迟有很大影响。
- `vk::Extent2D chooseSwapExtent(const vk::SurfaceCapabilitiesKHR& capabilities)`：这段代码的作用是为 Vulkan 交换链选择最终的图像尺寸（Extent），它会结合窗口的实际大小和硬件的支持范围，来确定渲染图像的宽高。

#### 2.实现交换链的具体属性
##### 第一步：配置交换链渲染缓冲帧的数量

首先，我们得到源文件中分别实现刚刚在头文件中签名的四个函数方法，它们是交换链创建的核心函数，用时后续操作也会使用上这些方法。所以我们首先实现这三个函数的具体内容。

**HelloTriangleApplication.cpp**

```cpp
uint32_t HelloTriangleApplication::chooseSwapMinImageCount(const vk::SurfaceCapabilitiesKHR& surfaceCapabilities)
{
    auto minImageCount = std::max(3u, surfaceCapabulities.minImageCount);
    if(surfaceCapabilities.maxImageCount > 0 && surfaceCapabilities.maxImageCount < minImageCount) {
        minImageCount = surfaceCapabilities.maxImageCount;
    }
    
    return minImageCount;
}
```

这是头文件创建的私有属性方法时创建的第一个函数方法，它是用来指定Vulkan交换链渲染帧能够支持的最小缓冲帧数量。具体解析如下：

- `auto minImageCount = std::max(3u, surfaceCapabilities.minImageCount)`：这里会返回一个`minImageCount`（最少需要的图像数），但这里我们把它和3取较大值。这样做是为了让交换链有更多缓冲图像，能更好地应对渲染波动，避免出现画面卡顿或撕裂。
- `surfaceCapabilities.maxImageCount > 0 && surfaceCapabilities.maxImageCount < minImageCount`：这里是确保交换链能够正常切换缓冲帧，同时检验设备的交换链是否有最大渲染帧的数量上限。
- `minImageCount = surfaceCapabilities.maxImageCount`：如果设备确实存在最大渲染帧的限制，那么就显示指定交换链的最小渲染缓冲帧为最大值，避免造成渲染失效的情况。
- `return minImageCount`：返回挑选后的结果，以备后续创建交换链时使用。

##### 第二步：配置交换链界面的格式

在设置完Vulkan交换链的图像缓冲帧数量后，接下来就需要显示设置交换链的交换界面的格式，它决定了图像渲染的颜色格式和颜色空间。具体的配置如下展示：

**HelloTriangleApplication.cpp**

```cpp
vk::surfaceFormatKHR HelloTriangleApplication::chooseSwapSurfaceFormat(const std::vector<vk::SurfaceFormatKHR>& availableFormats)
{
    assert(!availableFormats.empty() && "SwapSurface format not be empty");

    const auto& formatIt = std::ranges::find_if(availableFormats, 
        [](const auto& format) {
            return format.front == vk::Format::eB8G8R8A8Srgb && 
            format.colorSpace == vk::ColorSpaceKhr::eSrgbNonlinear;
        }
    );

    return formatIt != availableFormat.end() ? *formatIt :
    availableFormats[0];
}
```

- `assert(!availableFormats.empty() && "SwapSurface format not be empty")`：这是一个断言检查，确保传入的可用格式列表 `availableFormats`不为空。如果列表为空，程序会直接终止并输出错误信息，因为没有可用格式就无法创建交换链。
- ` const auto& formatIt = std::ranges::find_if()`：创建一个迭代器，去查询交换链容器中支持条件的交换链，并返回它位置的索引。
- `[](const auto& format) {}`：lambda表达式，这里用于快速筛选出满足需求的交换链。
- `return format.front == vk::Format::eB8G8R8A8Srgb && format.colorSpace == vk::ColorSpaceKhr::eSrgbNonlinear`：具体的筛件：
  - 颜色格式：`eB8G8R8A8Srgb`（这是最常用的一种格式，代表每个像素由蓝、绿、红、Alpha 四个通道组成，每个通道占 8 位，并且是 sRGB 色彩空间，适合直接显示在屏幕上）
  - 颜色空间：eSrgbNonlinear（对应 sRGB 非线性色彩空间，和显示器的显示特性匹配，能保证颜色显示更自然）
- `return formatIt != availableFormat.end() ? *formatIt :availableFormats[0]`：如果找到了我们想要的 `B8G8R8A8Srgb` + sRGB 组合，就返回这个格式。如果没找到，就退而求其次，直接返回列表中的第一个可用格式，保证程序能继续运行。

**注意：**

`vk::ColorSpaceKHR`是一个枚举类型，它拥有数个具体的枚举值，下面我们对它枚举值进行讨论。

###### 1.核心标准（KHR 扩展，基础必选）
- `vk::ColorSpaceKHR::eSrgbNonlinear`：这是最常用的色彩空间，对应 sRGB 非线性编码，适合普通显示器的 2D 渲染和游戏画面，能保证颜色显示自然。

###### 2.HDR 与专业色彩空间（EXT 扩展，需硬件支持）
- `vk::ColorSpaceKHR::eDisplayP3NonlinearEXT`：对应 Display-P3 色彩空间，色域比 sRGB 更宽，常用于专业设计、影视和高端显示器
- `vk::ColorSpaceKHR::eHdr10St2084EXT`：对应 HDR10 标准，使用 ST2084 电光转换函数（PQ），适合 HDR 视频和游戏，支持高动态范围显示。
- `vk::ColorSpaceKHR::eBt2020LinearEXT / eBt2020NonlinearEXT`：对应 BT.2020 色彩空间，是 UHDTV（超高清电视）的标准，用于专业视频处理。
- `vk::ColorSpaceKHR::eBt709LinearEXT / eBt709NonlinearEXT`：对应 BT.709 色彩空间，是高清电视（HDTV）的标准，常用于视频编码和播放。

###### 3.其他常见类型
- `vk::ColorSpaceKHR::eDciP3LinearEXT / eDciP3NonlinearEXT`：对应 DCI-P3 色彩空间，主要用于数字电影行业，是影院放映的标准。
- `vk::ColorSpaceKHR::eAdobeRgbLinearEXT / eAdobeRgbNonlinearEXT`：对应 Adobe RGB 色彩空间，色域比 sRGB 更宽，适合专业摄影和印刷。

##### 第三步：选择交换链图像的呈现模式

之后我们将对Vulkan交换链的图像呈现模式进行配置，它的作用是为 Vulkan 交换链选择最佳的图像呈现模式（Present Mode），它直接决定了渲染好的图像如何被送到显示器显示，对画面的流畅度和延迟有很大影响。

**HelloTriangleApplication.cpp**

```cpp
vk::PresentModeKHR HelloTriangleApplication::chooseSwapPresentMode(const std::vector<vk::PresentModeKHR>& availablePresentModes)
{
    assert(std::ranges::any_of(availablePresentModes, 
      [](auto PresentMode) {
          return presentMode == vk::PresentModeKHR::eFifo;
      }
    ));

    return std::ranges::any_of(availablePresentModes,
        [](const vk::PresentModeKHR value) {
            return vk::PresentModeKHR::eMailbox == value;
        }
    ) ? vk::PresentModesKhr::eMailbox : vk::PresentModeKHR::eFifo;
}
```

- `assert(std::ranges::any_of(availablePresentModes, [](auto PresentMode) {return presentMode ==vk::PresentModeKHR::eFifo;}))`：这是一个断言检查，确保设备支持 `eFifo` 模式。`eFifo` 是 Vulkan 强制要求所有设备都必须支持的模式，它的工作原理类似队列：显示器垂直同步刷新时，就从队列中取一张图像显示，没有图像就等待。
- `return std::ranges::any_of(availablePresentModes,[](const vk::PresentModeKHR value) {return vk::PresentModeKHR::eMailbox == value;}) ? vk::PresentModesKhr::eMailbox : vk::PresentModeKHR::eFifo`：这段代码会先检查设备是否支持 `eMailbox`（邮箱模式）。如果支持，就返回 `eMailbox`；如果不支持，就返回保底的 `eFifo` 模式。

**注意：**

###### 1.核心必选模式（所有设备都支持）

- `vk::PresentModeKHR::eFifo`：
  - 中文名称：FIFO（先进先出）模式（也叫 “垂直同步 VSync” 模式）
  - 工作原理：显示器有固定的刷新频率（如 60Hz），会周期性触发 “垂直消隐期”（VSync 信号）。Vulkan 会维护一个固定长度的图像队列（通常是 1 个），只有在 VSync 信号到来时，才从队列头部取出一张图像显示；如果队列空了，就等待渲染线程提交新图像。
  - 核心特点：
    - 绝对不会出现画面撕裂（因为只有刷新时才换图）；
    - 延迟较高（渲染好的图像必须等下一个 VSync 才能显示）
    -  若渲染帧率低于显示器刷新率（如 30fps 跑在 60Hz 显示器），会出现明显卡顿（比如每帧停留 2 个刷新周期）。
  - 适用场景：对画面稳定性要求高、不介意延迟的场景（如视频播放、办公软件）

- `vk::PresentModeKHR::eFifoRelaxed`：
  - 中文名称：宽松 FIFO 模式
  - 工作原理：是 `eFifo` 的 “宽松版”，核心逻辑和 FIFO 一致，但有一个关键区别：如果渲染线程提交图像晚于 VSync 信号（本该等待下一个周期），但图像到达时显示器还没开始新一帧的扫描，就会 “破例” 立即显示这张图像，不用等下一个 VSync。
  - 核心特点：
    - 基本无画面撕裂
    - 延迟比 `eFifo` 略低（避免不必要的等待）
    - 渲染帧率波动时，偶尔会出现帧时间不均匀的情况
  - 适用场景：想兼顾 VSync 稳定性和低延迟的通用场景（如普通游戏、UI 渲染）

###### 2.可选高性能模式（硬件不一定都支持）
- `vk::PresentModeKHR::eMailbox`：
  - 中文名称：邮箱模式（也叫 “无撕裂垂直同步”/“三重缓冲优化版”）
  - 工作原理：维护一个可变长度的图像队列（通常是 2~3 个），每次 VSync 信号到来时，直接取队列中最新的一张图像显示，队列中旧的未显示图像会被直接丢弃。
  - 核心特点：
    - 无画面撕裂（仅 VSync 时换图）
    - 延迟极低（始终显示最新渲染的帧）
    - 若渲染帧率远高于刷新率，会丢弃大量帧（但不影响观感）
  - 适用场景：对延迟敏感的场景（如竞技游戏、实时交互应用），是游戏开发的首选模式。

- `vk::PresentModeKHR::eImmediate`：
  - 中文名称：立即模式
  - 工作原理：完全无视 VSync 信号，渲染好的图像立即提交给显示器，不管显示器是否正在扫描画面。
  - 核心特点：
    - 延迟最低（几乎无等待）
    - 大概率出现画面撕裂（显示器扫描到一半时换图，上下部分是不同帧）
    - 渲染帧率无上限，可能造成 GPU 无意义的高负载
  - 适用场景：对延迟极致追求、可以接受撕裂的场景（如电竞游戏的 “关闭垂直同步” 模式）。

###### 3.扩展 / 特殊模式（需特定扩展 / 硬件支持）
- `vk::PresentModeKHR::eSharedDemandRefreshKHR`：
  - 中文名称：共享按需刷新模式
  - 工作原理：针对共享显示设备（如手机的多窗口、嵌入式设备）设计，只有当交换链有新图像提交时，才触发显示器刷新，否则显示器保持当前画面。
  - 适用场景：低功耗嵌入式设备、手机多窗口应用。

- `vk::PresentModeKHR::eSharedContinuousRefreshKHR`：
  - 中文名称：共享持续刷新模式
  - 工作原理：同样针对共享显示设备，但显示器会以固定频率持续刷新（即使没有新图像），保证画面的稳定性。
  - 适用场景：共享显示设备中对画面流畅度要求高的场景（如嵌入式游戏）。

##### 第四步：设置交换链的区域尺寸

最后我们来显示配置交换链的区域尺寸，它的作用是为 Vulkan 交换链选择最终的图像尺寸（Extent），它会结合窗口的实际大小和硬件的支持范围，来确定渲染图像的宽高。

**HelloTriangleApplication.cpp**

```cpp
vk::Extent2D HelloTriangleApplication::chooseSwapExtent(const vk::SurfaceCapabilitiesKHR& capabilities)
{
    if(capabilities.currentExtent.width != 0xFFFFFFFF) {
      return capabilities.currentExtent;
    }

    int width = 0;
    int height = 0;
    glfwGetFramebufferSize(window, &width, &height);

    vk::Extent2D actualExtent = {
        actualExtent.width = std::clamp<uint32_t>(width, capabilities.minImageExtent.width, capabilities.maxImageExtent.width);
        actualExtent.height = std::clamp<uint32_t>(height, capabilities.minImageExtent.height, capabilities.maxImageExtent.height);
    }

    return actualExtent;
}
```

- `if(capabilities.currentExtent.width != 0xFFFFFFFF) {return capabilities.currentExtent;}`：这是一个特殊判断：当 `currentExtent.width` 不等于 `0xFFFFFFFF`（即 `UINT32_MAX`）时，说明系统强制要求交换链图像尺寸必须和窗口原生尺寸完全一致。这种情况常见于移动设备或某些全屏模式，此时直接返回系统指定的 `currentExtent`即可。
- `glfwGetFramebufferSize(window, &width, &height);`：这一段代码是如果系统没有强制尺寸，就调用 `glfwGetFramebufferSize` 获取 GLFW 窗口的帧缓冲实际像素尺寸，这一步拿到的是窗口当前可用于渲染的真实像素宽高。
- `vk::Extent2D actualExtent = {actualExtent.width = std::clamp<uint32_t>(width, capabilities.minImageExtent.width, capabilities.maxImageExtent.width);actualExtent.height = std::clamp<uint32_t>(height, capabilities.minImageExtent.height, capabilities.maxImageExtent.height);}`：使用 `std::clamp` 函数，把窗口的宽高限制在硬件支持的范围内：
  - `capabilities.minImageExtent`：硬件支持的最小图像尺寸
  - `capabilities.maxImageExtent`：硬件支持的最大图像尺寸

#### 3.创建Vulkan交换链

经过一系列函数定义实现后，我们将开始正式创建Vulkan交换链，这一步操作将会在之前头文件中创建的签名函数中实现，因为交换链创建涉及Vulkan结构体，首先来了解一下该结构体的具体属性是什么。

**vk::SwapchainCreateInfoKHR**

前两个属性字段我们就不再讲解，毕竟已经提及过很多次了，大概的含义和用法或许大家已经一清二楚了。直接转向结构体后面几个属性作用，下面我们来一一解释。

###### 1.基础配置
- `vk::SwapchainCreateFlagsKHR flags_ = {}`：交换链的创建标志，目前 Vulkan 规范里没有定义任何可用标志，通常留空。
- `vk::SurfaceKHR surface_ = {}`：要绑定的 Vulkan 窗口表面（`VKSurfaceKHR`），也就是之前创建的 `surface` 对象，它是交换链和窗口之间的桥梁。

###### 2.图像数量与格式
- `uint32_t minImageCount_ = {}`：交换链最少需要包含的图像数量，就是之前 `chooseSwapMinImageCount` 函数返回的值。
- `vk::Format imageFormat_ = {}`：交换链图像的像素格式，比如 `eB8G8R8A8Srgb`，由 `chooseSwapSurfaceFormat` 决定。
- `vk::ColorSpaceKHR imageColorSpaceKHR_ = {}`：交换链图像的色彩空间，比如 `eSrgbNonlinear`，同样由 `chooseSwapSurfaceFormat` 决定。

###### 3.图像尺寸与分层
- `vk::Extent2D imageExtent_ = {}`：交换链图像的尺寸（宽高），就是 `chooseSwapExtent` 返回的结果，决定了渲染图像的像素大小。
- ` uint32_t imageArrayLayers_ = {};`：交换链图像的层数，默认是 1（单图层），只有做立体 VR 渲染时才会设为 2（左右眼双图层）。

###### 4.图像用途与共享模式
- `vk::ImageUsageFlags imageUsage_ = {}`：交换链图像的用途，通常设置为 `COLOR_ATTACHMENT_BIT`（作为渲染目标）和 `TRANSFER_DST_BIT`（作为传输目标）。
- `vk::SharingMode imageSharingMode_ = {}`：图像的队列共享模式：
  - `eExclusive`：交换链图像只归一个队列家族独占（默认，性能最好）
  - `eConcurrent`：允许多个队列家族同时访问图像（需要下面两个字段配合）
- `uint32_t queueFamilyIndexCount_ = {}`和 `pQueueFamilyIndices_`：当 `imageSharingMode_`为 `eConcurrent` 时，用来指定可以访问该图像的队列家族索引列表。

###### 5.变换与合成
- `preTransform_`：图像在显示前的变换方式，通常设为 `eIdentity`（无变换），也可以设置旋转、镜像等。
- `compositeAlpha_`：混合 alpha 通道的方式，用来处理透明窗口的合成，一般设为 `eOpaque`（不透明，性能最好）。

###### 6.呈现模式与裁剪
- `presentMode_`：交换链的呈现模式，就是 `chooseSwapPresentMode` 返回的结果（如 `eMailbox`、`eFifo`）
- `clipped_`：是否允许裁剪超出窗口区域的图像，设为`true`时，驱动会自动裁剪掉窗口外的像素，提升性能。 

###### 7.旧交换链与指针
- `oldSwapchain_`：如果是重建交换链（比如窗口大小改变时），这里填旧的交换链句柄，驱动会自动复用旧资源，提升重建效率。
- `pNext_`：指向扩展结构的指针，用来传递 Vulkan 核心规范之外的扩展参数，比如 HDR 相关的扩展信息。

---

#### 4.显示配置交换链结构体

在了解了交换链结构体中每一个属性的大概含义后，接下来我们就正式开始配置Vulkan交换链的完整结构体属性了，这是十分重要的一步，它决定着我们的图像最后能否正确展示出来。其结构体的具体配置如下显示：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateSwapChain()
{
  auto surfaceCapabilities = physicalDevice.getSurfaceCapabilitiesKHR(*surface);
  swapChainExtent = chooseSwapExtent(surfaceCapablilities);
  swapChainSurfaceFormat = chooseSwapSurfaceFormat(physicalDevice.getSurfaceFormatsKHR(*surface));

  vk::SwapchainCreateInfoKHR swapChainCreateInfo = {
    swapChainCreateInfo.flags = {},
    swapChainCreateInfo.surface = *surface,
    swapChainCreateInfo.minImageCount = chooseSwapMinImageCount(surfaceCapabilities),
    swapChainCreateInfo.imageFormat = swapChainSurfaceFormat.format,
    swapChainCreateInfo.imageColorSpace = swapChainSurfaceFormat.colorSpace,
    swapChainCreateInfo.imageExtent = swapChainExtent,
    swapChainCreateInfo.imageArrayLayers = 1,
    swapChainCreateInfo.iamgeUsage = vk::ImageUsageFlagBits::eColorAttachment,
    swapChainCreateInfo.imageSharingMode = vk::SharingMode::eExclusive,
    swapChainCreateInfo.queueFamilyIndexCount = 0,
    swapChainCreateInfo.pQueueFamilyIndices = nullptr,
    swapChainCreateInfo.preTransform = surfaceCapabilities.currentTransform,
    swapChainCreateInfo.compositeAlpha = vk::CompositeAlphaFlagBits::eOpaque,
    swapChainCreateInfo.presentMode = chooseSwapPresentMode(physicalDevice.getSurfacePresentModesKHR(*surface)),
    swapChainCreateInfo.clipped = true,
    swapChainCreateInfo.oldSwapchain = nullptr,
    swapChainCreateInfo.pNext = nullptr
  }
}
```

在上面的代码中，我们展示了一个完整的显示配置属性字段的Vulkan交换链结构体，以及一些属性字段需要辅助函数和变量。下面将展开对每个属性配置的解释：

###### 基础属性配置
- `flags_`：这是交换链结构体的标志位属性，这里留空白方便以后扩展。
- `surface_`：交换链结构体的渲染界面属性，交换链的图形切换窗口需要依赖Vulkan的渲染界面为前提，这里将之前创建的`surface`作为依赖的对象，用于告诉交换链我们需要将切换窗口创建在这个渲染界面上。

###### 图像数量与格式
- `minImageCount`：此属性是交换链切换图像时允许同时存在的最小图像数量，这里用创建的辅助函数`chooseSwapMinImageCount`来获取设备支持的最小图像切换数量。
- `imageFormat`：这是交换链图像交换区域的格式属性，这里用`swapChainSurfaceFormat.format`属性来配置。
- `imageColorSpace`：这是交换链图像区域颜色空间的属性，这里设置设置为`swapChainSurfaceFormat.colorFormat`的值。

###### 图像尺寸与分层
- `imageExtent`：这是交换链图像切换区域的尺寸大小属性，在这里我们显示指定为`chooseSwapChainExtent`变量的值。
- `imageArrayLayers`：该属性是交换链图层数量，由于该项目是单一屏幕渲染，需要保持图层数量为1，因此显式指定图层数量为1层。

#### 5.保存交换链结构体

上面我们也将Vulkan交换链结构体通过显示指定属性配置完成了，一切已经准备就绪，接下来就是把交换链的实例对象用属性字段保存起来，供后续Vulkan的流程使用。具体的内容如下展示：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateSwapChain()
{
  swapChain = vk::raii::SwapchainKHR(device, swapChainCreateInfo);
  if(swapChain == nullptr) {
    std::cerr << "Vulkan swap chain Create failed!" << std::endl;
    return;
  }
  std::clog << "Vulkan swap chain Create success!" << std::endl;
  swapChainIamges = swapChain.getImages();
}
```

- `swapChain = vk::raii::SwapchainKHR(device, swapChainCreateInfo)`：之前头文件中创建的交换链属性实例对象用来保存并绑定到逻辑设备上。
- `swapChain == nullptr`：简易的判断交换链的指针是否指向空地址，如果为空就输出错误日志。
- `swapChainImages = swapChain.getImages()`：获取交换链中全部的图像信息，同时交给`swapChainImages`向量容器来保存。
