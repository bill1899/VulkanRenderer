## Vulkan队列家族和队列的创建流程（The process of Vulkan queueFamily and queue）

上一节中，我们详细了解了如何在Vulkan中创建逻辑设备，逻辑设备的创建对于Vulkan的初始化的过程极为重要，有了它才能对Vulkan的下达和修改指令，这个过程就好比工厂中工程师通过每个设备提供的显示界面，操作设备执行不同的生产任务，而这里的显示界面就相当于Vulkan中的逻辑设备，相信这样一个实际的例子会加深你对逻辑设备的印象。那么接下来，我们将会对Vulkan**队列家族**和**队列**的创建进行深入的探讨。

---

### 队列和队列家族的创建流程
#### 1.创建头文件契约

在这一章节中我们需要先做的事情，仍然还是在头文件中创建契约签名，这些签名的属性字段将作为队列和队列家族的存储单元供后续使用。具体的创建过程展示如下：

**HelloTriangleApplication.h**

```cpp
class HelloTriangleApplication
{
private:
    GLFWwindow*                        window          = nullptr;     //窗口属性
    vk::raii::Context                  context;                       //Vulkan上下文
    vk::raii::Instance                 instance        = nullptr;     //Vulkan实例
    vk::raii::DebugUtilsMessengerEXT   debugMessager   = nullptr;     //Vulkan验证层
    vk::raii::PhysicalDevice           physicalDevice  = nullptr;     //物理设备
    vk::raii::Device                   device          = nullptr;     //逻辑设备
    uint32_t                           queueIndex      = ~0;          //队列索引（新添加）
    vk::raii::Queue                    graphicsQueue   = nullptr;     //图形队列（新添加）
};
```

##### 第一步：创建私有属性字段

    uint32_t queueIndex = ~0;  //队列索引（新添加）
    vk::raii::Queue graphicsQueue = nullptr;  //图形队列（新添加）

这里，我们仍然在头文件的类私有属性区域中创建了两个属性字段`queueIndex`和`graphicsQueue`。它们就是本章节的重点操作对象。

- `uint32_t queueIndex = ~0`：这是 Vulkan 开发中的一种约定俗成的写法，用来初始化一个 “无效的队列族索引”，表示 “尚未找到合适的队列族”，本质上是表示32为整型数字的能表示的最大值。
- `vk::raii::Queue graphicsQueue`：这是Vulkan队列家族的属性字段，主要用来存储同一队列家族的所有队列，比如图形队列、计算队列、传输队列。

---

#### 2.查询队列家族类型支持

第二步，我们需要跳转到源文件中进一步实现Vulkan队列和队列家族的具体创建过程，首先要做的操作就是查询Vulkan支持的队列家族，如果查询的队列家族支持就代表着我们可以使用该家族下的具体队列，能够进步利用它来执行渲染命令。具体展示如下：

**HelloTriangleApplication.h**

```cpp
void HelloTriangleApplication::CreateLogicalDevice()
{
    //查询物理设备支持的队列家族
    std::vector<vk::QueueFamilyProperties> queueFamilyProperties = physicalDevice.getQueueFamilyProperties();

    //从结果中选取第一个符合要求的队列家族
    auto graphcisQueueFamilyProperty = std::ranges::find_if(queueFamilyProperty,
        [](const auto& qfp){
            return (qfp.queueFlags & vk::QueueFlagBits::eGraphics) != static_cast<vk::QueueFlags>(0);
        }    
    );

    //断言：必须找到图形队列族，否则程序终止并提示
    assert(graphcisQueueFamilyProperty != queueFamilyProperties.end() && "NO graphics queue family found!");

    //计算并保存图形队列族的索引
    queueIndex = static_cast<uint32_t>(std::distance(queueFamilyProperties.begin(),graphicsQueueFamilyProperty));
}
```

这段代码是Vulkan中筛选物理设备图形队列族的核心逻辑，整体作用是从物理设备支持的所有队列族中，找到第一个具备图形功能的队列族，并记录它的索引 —— 这是创建逻辑设备、后续提交图形指令的前提。

---

##### 第一步：查询物理设备的所有队列族

     std::vector<vk::QueueFamilyProperties> queueFamilyProperties = physicalDevice.getQueueFamilyProperties();

- `physicalDevice`：Vulkan 的物理设备对象，对应你的显卡
- `getQueueFamilyProperties()`：Vulkan 提供的 API，返回该物理设备支持的所有队列族属性列表
- `vk::QueueFamilyProperties`：队列族属性结构体，包含该队列族的功能（比如是否支持图形、计算、传输）、队列数量等关键信息
- `queueFamilyProperties`：容器的实例对象，其中每个元素都是`vk::QueueFamilyProperties`类型的队列家族属性


##### 第二步：查找第一个图形队列族

    auto graphcisQueueFamilyProperty = std::ranges::find_if(queueFamilyProperty,
        [](const auto& qfp){
            return (qfp.queueFlags & vk::QueueFlagBits::eGraphics) != static_cast<vk::QueueFlags>(0);
        }    
    );

- `std::ranges::find_if`：C++20 新增的范围遍历函数，作用是遍历容器，找到第一个满足 Lambda 条件的元素
- Lambda 表达式是核心判断逻辑：
  - `qfp.queueFlags`：当前队列族支持的功能标志位（是一个按位存储的枚举）

  - `vk::QueueFlagBits::eGraphics`：**图形功能**的标志位，所有需要渲染 3D/2D 图形的应用都必须依赖这个队列族，他还有其他几个标志位，展示如下：
    - `vk::QueueFlagBits::eCompute`：**计算队列**，支持通用计算指令（Compute Shader），可以执行与图形无关的并行计算任务。
    - `vk::QueueFlagBits::eTransfer`：**传输队列**，专门处理数据复制、内存传输指令（比如从 CPU 内存向 GPU 显存复制纹理 / 缓冲区）。
    - `vk::QueueFlagBits::eGraphicsARM`：**ARM 硬件专用图形队列**，ARM 架构 GPU（比如手机、平板的 Mali 系列）的专用图形队列优化，用来适配 ARM 硬件的特定渲染流水线。
    - `vk::QueueFlagBits::eOpticalFlowNV`：**NVIDIA 光流队列**，支持 NVIDIA GPU 的光流硬件加速功能，用于计算视频帧之间的像素运动向量。
    - `vk::QueueFlagBits::eProtected`： **受保护队列**，支持受保护内存（Protected Memory），可以处理加密的内容（比如 DRM 保护的视频），防止数据被非法访问或泄露。
    - `vk::QueueFlagBits::eSparseBinding`：**稀疏绑定队列**，支持稀疏内存绑定（Sparse Memory Binding），可以将大型资源（比如 4K/8K 纹理）的部分区域映射到显存，节省内存。
    - `vk::QueueFlagBits::eVideoDecodeKHR /eVideoEncodeKHR`：**视频编解码队列**，支持硬件加速的视频解码 / 编码（比如 H.264、H.265、AV1），由 VK_KHR_video_queue 扩展提供。
  
  - `&`是按位与运算：只有当 queueFlags 中包含 eGraphics 位时，结果才非 0
  - 整体逻辑：判断当前队列族是否具备图形功能（这是渲染图形的核心队列）


##### 第三步：断言检查：必须找到图形队列族

    assert(graphcisQueueFamilyProperty != queueFamilyProperties.end() && "NO graphics queue family found!");

- `assert` 是调试阶段的断言：如果条件不满足（没找到图形队列族），程序会直接终止，并输出后面的提示字符串
- 原因：图形队列是 Vulkan 渲染的核心，没有图形队列的物理设备（比如纯计算卡）无法用于图形渲染，必须终止程序
- 注意：`assert` 仅在调试模式生效，发布模式会被忽略，生产环境建议替换为显式的错误处理逻辑。


##### 第四步：计算图形队列族的索引

    queueIndex = static_cast<uint32_t>(std::distance(queueFamilyProperties.begin(),graphicsQueueFamilyProperty));

- `std::distance`：计算两个迭代器之间的元素个数，也就是 “找到的图形队列族” 在向量中的下标位置
- `static_cast<uint32_t>`：把下标（默认是 `ptrdiff_t` 类型）转为 Vulkan 要求的 `uint32_t` 类型
- `queueIndex`：最终保存的是图形队列族的索引（比如 0、1 等），后续创建逻辑设备时，需要用这个索引指定要创建的队列族。

---

#### 3.创建并配置队列家族结构体

接下来，我们又轮到了给Vulkan结构体显示指定配置的时候了，当然在正式指定机构体配置之前，我们需要了解队列家族结构体需要哪些属性字段，这样会更有利于知识体系的构建。具体内容展示如下：

**vk::DeviceQueueCreateInfo**

```cpp
struct DeviceQueueCreateInfo
{
    static const bool allowDuplicate = false;
    static StructureType sturctureType = StructureType::eDeviceQueueCreateInfo;

    DeviceQueueCreateFlags flags_            = {};
    uint32_t               queueFamilyIndex_ = {};
    uint32_t               queueCount_       = {};
    const float*           pQueuePriorities_ = {};
    const void*            pNext_            = nullptr;  
};
```

前两个属性我们不再过多赘述，毕竟已经谈论过很多回了，没必要在重复探讨。直接进入后面属性的探讨更加实在。

    DeviceQueueCreateFlags flags_            = {};
    uint32_t               queueFamilyIndex_ = {};
    uint32_t               queueCount_       = {};
    const float*           pQueuePriorities_ = {};
    const void*            pNext_            = nullptr;  

###### 队列族配置核心参数
- `DeviceQueueCreateFlags flags_ = {}`：队列创建的标志位，目前 Vulkan 规范里没有定义任何可用的标志，所以通常留空为 {}。未来扩展时可能会加入新的队列创建选项。
- `uint32_t queueFamilyIndex_ = {}`：你要配置的队列族的索引（比如图形队列族的索引、计算队列族的索引）。这个值来自你之前筛选队列族时得到的 `queueIndex`，是整个结构体的核心。
- `uint32_t queueCount_ = {}`：在这个队列族下要创建的队列数量。比如你想创建 2 个图形队列，就把这个值设为 2
- `const float* pQueuePriorities_ = {}`：指向一个 float 数组的指针，数组长度等于 `queueCount_`，每个元素表示对应队列的优先级（范围 `0.0f`~`1.0f`，值越高优先级越高）。

###### 扩展指针
- `const void* pNext_ = nullptr`：Vulkan 的扩展机制核心，用来链接扩展特性链。比如你要启用某些和队列相关的扩展特性，就需要把对应的扩展结构体通过 `pNext_` 挂到这里，告诉驱动要启用该扩展。大部分场景下这个值可以设为 `nullptr`。

---

##### 配置结构体属性

在上面，我们了解了该结构体的所有属性的具体含义，这样就能确保在配置过程知道该使用什么数据来填充，那么接下来就正式开始显示配置结构体属性了。

**HelloTriangleApplication.h**

```cpp
void HelloTriangleApplication::CreateLogicalDevice()
{
    //在逻辑设备特性之后插入

    float queuePriority = 0.5f;
    vk::DeviceQueueCreateInfo deviceQueueCreateInfo = {
        deviceQueueCreateInfo.flag_ = {},
        deviceQueueCreateInfo.queueFamilyIndex_ = queueIndex,
        deviceQueueCreateInfo.queueCount_ = 1,
        deviceQueueCreateInfo.pQueuePriorities_ = &queuePriority,
        deviceQueueCreateInfo.pNext_ = nullptr
    };

    //在逻辑设备结构体创建之前插入
}
```

#### 4.补充逻辑设备结构体

由于上一章节中，逻辑设备的结构体属性并不非常完善，它缺少了队列家族的属性，因此我们在这里会把逻辑结构体的属性补充完整。接下来就是完整的代码展示，展示一个完整的逻辑结构体的属性配置，具体如下：

**HelloTriangleApplication.h**

```cpp
void HelloTriangleApplication::CreateLogicalDevice()
{
    vk::DeviceCreateInfo deviceCreateInfo = 
	deviceCreateInfo.flags = {},
	deviceCreateInfo.queueCreateInfoCount = 1,
	deviceCreateInfo.pQueueCreateInfos = &deviceQueueCreateInfo,
	deviceCreateInfo.enabledLayerCount = 0,
	deviceCreateInfo.ppEnabledLayerNames = nullptr,
	deviceCreateInfo.enabledExtensionCount = static_cast<uint32_t>(requiredDeviceExtension.size()),
	deviceCreateInfo.ppEnabledExtensionNames = requiredDeviceExtension.data(),
	deviceCreateInfo.pEnabledFeatures = nullptr,
	deviceCreateInfo.pNext = featuresChain.get(),
};
```
