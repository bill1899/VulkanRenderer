## Vulkan物理设备的选取流程（The process of choose Vulkan physicalDevice）

在上一节中，我们成功的为Vulkan添加了扩展属性，这些扩展属性确保了Vulkan能够与GLFW窗口和Vulkan验证层配合，为我们在开发程序的过程中保驾护航。那么在这一节中，我们将会选取Vulkan的物理设备，这里的物理设备选取并不是特别抽象都操作步骤，相反这个步骤其实很容易理解，只不过你需要换一个解释说明的方法。还记得之前我们说的Vulkan的初始化创建过程可以比喻为一个工厂搭建的过程吗？如果你照着这个思路继续联想下去，你会惊喜的发现Vulkan初始化过程的每一步都能在工厂比喻中找到对应的步骤。当然，这里我们不会展开来讲具体的对应关系，我们只关注当前的重点：**Vulkan物理设备的选取**。

---

### 物理设备的选取流程
#### 1.创建头文件签名契约

对计算机有过了解的都知道，现代的计算机内部结构是很复杂的，它是由多个组件共同组成的能够使用的计算设备，在这里我们不需要对它的每一个组件都要了解深刻，我们只需重点关注其中一个核心组件：**GPU**，这个组件是现代计算机高效运行的关键物理设备，这个组件它确实存在着不同型号的差距，而这个差距主要是由它内部的硬件和结构设计导致的计算能力差异造成的结果，当然我们不否定这一客观存在的事实，只追求能够平衡不同设备计算能力的差异，这时Vulkan的作用就显得尤其重要。

我们不妨想象一下，不同的GPU会存在计算能力方向的差异，这一点就好比工厂里的生产设备它们之间事实存在的生产效率差异，但是任务的总体体量决定了我们选择哪种生产效率的设备是最高效且成本最低的方案，体量大、时间紧的任务我们选择高效率的设备去完成生产任务，体量小、时间要求宽松的任务我们就选择效率较低但灵活的设备去完成，不论那种方案其最终目的都是为让整个工厂以最适合的方案完成任务。当然Vulkan物理设备的选择和我们这里列出的工厂例子思路基本相同。那么接下来我们就开始选取物理设备的流程吧。

#### 2.列举Vulkan支持的物理设备

从这里开始，我们将关注的重点转移到`pickPhysicalDevice`函数方法在源文件中的的具体实现，它是非常关键的一步，所以我们要打起十分的精神，了解Vulkan物理的设备的选取是如何实现的。

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::pickPhysicalDevice()
{
    //列举Vulkan支持的物理设备
    auto devices = instance.enumeratePhysicalDevice();
    if(devices.empty()) {
        throw std::runtime_error("Failed to find GPUs with Vulkan support!");
    }
}
```

这段代码中，我们先创建一个vector类型的容器来存储该实例支持的Vulkan物理设备，接着判断该容器是否内部是否存在元素，如果没有就代表该实例不支持任何的物理设备，否则该实例支持一定数量的物理设备。

#### 3.判断是否支持物理设备特性

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::pickPhysicalDevice()
{
    //上面代码保持不变

    const auto devIter = std::ranges::find_if(devices, 
        [&](auto& device) {
            //检查物理设备是否支持Vulkan的版本
            bool supportVulkan1_4 = device.getProperties().apiVersion >= vk_API_VERSION_1_4;
            //等价于<=> 
            /*vk::PhysicalDeviceProperties temp;
            temp.apiVersion >= VK_API_VERSION_1_4;*/

            auto queueFamilies = device.getQueueFamilyProperties();
            bool supportGraphics = std::ranges::any_of(queyeFamilies, 
            [](const auto& qfp) {
                return !!(qfp.queueFlags & vk::QueueFlagsBits::eGraphics);
            }
            )

            auto availableDeviceExtensions = device.enumerateDeviceExtensionProperties();
            bool supportAllRequiredExtension = std::ranges::all_of(requiredDeviceExtension, 
            [&availableDeviceExtensions](const auto& requiredDeviceExtension) {
                return std::ranges::any_of(availableDeviceExtensions, 
                [requiredDeviceExtension](const auto& availableDeviceExtension) {
                    return strcmp(availableDeviceExtension.extensionName, requiredDeviceExtension) == 0;}
                );}
            );}
        );
}
```

##### 第一步：筛选Vulkan的版本支持

    bool supportVulkan1_4 = device.getProperties().apiVersion >= vk_API_VERSION_1_4;

- 调用 `getProperties()` 获取设备的基础属性
- 检查设备支持的 Vulkan API 版本是否 ≥ 1.4
- 确保设备能运行基于 Vulkan 1.4 开发的功能

##### 第二步：检查图形队列族

    auto queueFamilies = device.getQueueFamilyProperties();
    bool supportGraphics = std::ranges::any_of(queyeFamilies, 
        [](const auto& qfp) {
            return !!(qfp.queueFlags & vk::QueueFlagsBits::eGraphics);
        }
    )

- `getQueueFamilyProperties()`：获取设备支持的所有队列族信息
- `std::ranges::any_of`：遍历所有队列族，判断是否存在至少一个支持图形队列（`Graphics`）的队列族
- 这是渲染 3D 图形的基础，没有图形队列就无法绘制三角形、游戏画面等内容

##### 第三步：验证所需设备扩展

    auto availableDeviceExtensions = device.enumerateDeviceExtensionProperties();
    bool supportAllRequiredExtension = std::ranges::all_of(requiredDeviceExtension, 
        [&availableDeviceExtensions](const auto& requiredDeviceExtension) {
            return std::ranges::any_of(availableDeviceExtensions, 
                [requiredDeviceExtension](const auto& availableDeviceExtension) {
                    return strcmp(availableDeviceExtension.extensionName, requiredDeviceExtension) == 0;
                }
            );
        }
    );

- `enumerateDeviceExtensionProperties()`：获取设备支持的所有 Vulkan 扩展
- `std::ranges::all_of`：确保所有程序需要的扩展都在设备支持的列表里
- 内层的 `std::ranges::any_of`：检查单个所需扩展是否在设备的支持列表中

整个 `std::ranges::find_if` 会遍历所有设备，第一个同时满足「版本≥1.4」「有图形队列」「支持所有扩展」这三个条件的设备会被选中，它的迭代器会被存在 `devIter` 里。

#### 4.检查特性支持

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::pickPhysicalDevice()
{
    //上面代码保持不变

    const auto devIter = std::ranges::find_if(devices, 
        
        //上面代码保持不变

        vk::StructureChain<
            vk::PhysicalDeviceFeatures2,
            vk::PhysicalDeviceVulkan13Features,
            vk::PhysicalDeviceVulkan14Features,
            vk::PhysicalDeviceExtensionDynamicStateFeaturesEXT
        > featuresChain;

        auto& features2 = featuresChain.get<vk::PhysicalDeviceFeatures2>();
        auto& vulkan13Features = featuresChain.get<vk::PhysicalDeviceVulkan13Features>();
        auto& extendedDynamicStateFeatures = featuresChain.get<vk::PhysicalDeviceExtensionDynamicStateFeaturesEXT>();

        bool supportRequiredFeatures = vulkan13Features.dynamicRendering && extendedDynamicStateFeatures.extendedDynamicState;

        return supportVulkan1_4 && supportGraphics && supportAllRequiredExtension && supportRequiredFeatures;
        );
}
```

##### 第一步：构建 Vulkan 特性链

    vk::StructureChain<
        vk::PhysicalDeviceFeatures2,
        vk::PhysicalDeviceVulkan13Features,
        vk::PhysicalDeviceVulkan14Features,
        vk::PhysicalDeviceExtensionDynamicStateFeaturesEXT
    > featuresChain;

- `vk::StructureChain`：Vulkan 提供的便捷工具，用来组合多个「特性结构体」，避免手动管理 Vulkan 结构体的 pNext 链表（这是 Vulkan 扩展特性的核心机制）。
- 这里组合了 4 个结构体：
  - `PhysicalDeviceFeatures2`：基础特性容器（Vulkan 1.1+ 标配）
  - `PhysicalDeviceFeatures2`：基础特性容器（Vulkan 1.1+ 标配）
  - `PhysicalDeviceVulkan14Features`：Vulkan 1.4 新增的核心特性
  - `PhysicalDeviceExtensionDynamicStateFeaturesEXT`：EXT 扩展定义的「扩展动态状态」特性。
  
##### 第二步：获取特性结构体的引用

    auto& features2 = featuresChain.get<vk::PhysicalDeviceFeatures2>();
    auto& vulkan13Features = featuresChain.get<vk::PhysicalDeviceVulkan13Features>();
    auto& extendedDynamicStateFeatures = featuresChain.get<vk::PhysicalDeviceExtensionDynamicStateFeaturesEXT>();

- `featuresChain.get<类型>()`：从特性链中取出对应类型的结构体引用，方便后续检查具体特性。
- 注意：`features2` 在这里只是占位（Vulkan 要求特性链必须以 `PhysicalDeviceFeatures2` 开头），代码里没直接用，但它是整个特性链的 “根”。

##### 第三步：检查关键功能是否支持

    bool supportRequiredFeatures = vulkan13Features.dynamicRendering 
    && extendedDynamicStateFeatures.extendedDynamicState;

- `dynamicRendering`（Vulkan 1.3 核心特性）
  - 中文叫「动态渲染」，是 Vulkan 1.3 的核心优化特性
  - 作用：允许将更多渲染状态（如多边形模式、线宽、深度测试参数等）设置为动态状态，无需在管线布局中提前固定

- `extendedDynamicState`（EXT 扩展特性）
  - 中文叫「扩展动态状态」
  - 作用：允许将更多渲染状态（如多边形模式、线宽、深度测试参数等）设置为动态状态，无需在管线布局中提前固定

##### 第四步：最终筛选条件

    return supportVulkan1_4 && supportGraphics && supportAllRequiredExtension && supportRequiredFeatures;

- 只有同时满足以下 4 个条件的设备才会被选中：
  - 1.支持 Vulkan 1.4 及以上版本。
  - 2.拥有图形队列族。
  - 3.支持所有必需的设备扩展。
  - 4.支持「动态渲染」和「扩展动态状态」特性。

##### 第五步：获取筛选结果

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::pickPhysicalDevice()
{
    //上面代码保持不变

    if(devIter != devices.end()) {
        physicalDevice = *devIter;
        if(physicaDevice == nullptr) {
            std::cerr << "Vulkan physical device pick failed!" << std::endl;
            return;
        }
        std::clog << "Vulkan physical device pick success!" << std::endl;
    }
    else {
        throw std::runtime_error("Failed to find a suitable GPU!");
    }
}
```

最后，我们通过一个完整的条件判断和异常处理来获取最后是否有物理设备同时满足我们之前提及的所有条件。

- `devIter != devices.end()`：判断迭代器`devIter`的当前位置是否在物理设备容器末尾，如果不是就代表着存在满足条件的物理设备。
- `physucalDevice = *devIter`：将满足条件的物理设备拷贝一份给属性字段存储。
- `std::runtime_error("Failed to find a suitable GPU!")`：如果没有找到满足条件的物理设备，抛出运行时异常，防止程序直接崩溃。
