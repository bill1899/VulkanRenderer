## Vulkan扩展层添加的流程（The process of add Vulkan extensionLayer）

上面一节中，我们试着亲手创建了Vulkan的验证层，虽然流程是很繁琐的，但是对于开发Vulkan相关的应用程序，如果没有验证层的提供的信息反馈，那么在调试环节就是一个巨大灾难，这会让我们提供极大一部分精力，来面对随时性的无征兆的问题，所以对于启用Vulkan的验证层是非常必要的步骤。

---

### 扩展层的添加流程
#### 1.创建文件契约签名

接下来，我们将介绍如何创建Vulkan扩展层的完整流程。首先我们还是得再头文件中声明契约，但这章节不同的是我们不需要在私有属性中声明任何属性字段，因为这章节中使用不到，相应的的我们得去私有的函数方法区声明一个名为`getRequiredExtensions()`的方法用于创建Vulkan扩展属性的函数方法。具体内容如下：

**HelloTriangleApplication.h**

```cpp
class HelloTriangleApplication
{
private:
    void initVulkan();
    void mainLoop();
    void cleanUp();
    void initWindow();
    void CreateInstance();
    
    void setupDebugMessager();
    static VKAPI_ATTP vk::Bool32 VKAPI_CALL debugCallback(
        vk::DebugUtilsMessageSeverityFlagsEXT severity,
        vk::DebugUtilsMessageTypeFlagBitsEXT type,
        const vk::DebugUtilsMessengerCallbackDataEXT* CallbackData,
        void*);
        
    std::vector<const char*> getRequiredExtensions(); //声明扩展创建的函数方法
}
```

---

#### 2.源文件定义具体实现

当然既然我们我们在头文件中声明了契约，那就得在源文件中定义该函数方法得具体实现，该函数得具体实现内容如下：

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplciation::getRequiredExtensions()
{
    uint32_t glfwExtensionCount = 0; //glfw的扩展数量
    auto glfwExtensions = glfwGetRequiredInstanceExtensions(&glfwExtensionCount); //获取Vulkan需要的glfw需要的扩展属性

    std::vector extensions(glfwExtensions, glfwExtensions + glfwExtensionCount); //将原始数组转换为C++的vector
    if(enableValidationLayers) {
        extensions.push_back(vk::EXTDebugUtilsExtensionName);
    }
    return extensions;
}
```

在这段代码中，我们主要获取了GLFW库的扩展属性支持，我们在学习Vulkan就讲过Vulkan是一个但图形渲染的库，它不提供任何的窗口输出界面，只要没有显示指定窗口的扩展库，那么Vulkan就无法将渲染好的图形通过窗口可视化输出，所以我们必须显示让Vulkan知道我们使用的窗口库是GLFW库，让它在渲染完所有的图形后通过GLFW窗口把结果可视化输出。

    uint32_t glfwExtensionCount = 0;
    auto glfwExtensions = glfwGetRequiredInstanceExtensions(&glfwExtensionCount);

这两行代码是本函数方法实现的第一部分，主要是通过整型局部变量`glfwExtensionCount`作为GLFW库提供的扩展属性获取的接口方法`glfwGetRequiredInstanceExtensions()`去获取具体的GLFW窗口扩展属性。并通过`glfwExtensions`变量去接受该函数返回的原始数组。

    std::vector extensions(glfwExtensions, glfwExtensions + glfwExtensionCount); 
    if(enableValidationLayers) {
        extensions.push_back(vk::EXTDebugUtilsExtensionName);
    }
    return extensions;

这是第二部分主要代码，在这里我们首先通过C++17特性的**模板智能推导**创建了一个向量容器`extensions`，它的目标是将`glfwExtensions`原始数组的数据拷贝到C++的vector容器中，这样做是为了更好的对容器中的数据进行处理和修改。这里我们用到了vector容器的指针构造函数，我们把`glfwExtensions`和`glfwExtensions + glfwExtensionCount`作为参数传入，这样vector容器就能顺利将原始数组数据拷贝给自己存储了。接着我们判断Vulkan验证层是否开启，如果开启了验证层我们就把验证层的扩展属性名添加到容器中，最后我们返回这个vector容器的拷贝份供后续使用。

---

#### 3.查询扩展属性支持能力

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateInstance()
{
    //上面代码保持不变

    auto requiredExtensions = getRequiredExtensions();
    auto extensionProperties = context.enumerateInstanceExtensionProperties();
    for(const auto& requiredExtension : requiredExtensions) {
        if(std::ranges::none_of(extensionProperties, 
            [requiredExtension](const auto& extensionProperty) {
                return strcmp(extensionProperty.extensionName, requiredExtension) == 0;
            }
        ))
        {
            throw std::runtime_error("Required extension not supported:" + std::string(requiredExtension));
        }
    }
}
```

这里我们依旧延续之前的思路，通过`requiredExtensions`变量获取GLFW库的扩展支持以及验证层的扩展支持。接着，我们使用Vulkan提供的查找函数`enumerateInstanceExtensionProperties()`列举并找出该实例能够支持的扩展属性，然后分别遍历`requiredExtensions`和`extensionProperties`两个容器中的扩展属性，如果Vulkan实例的支持我们的指定的扩展属性，那么我们就会在后续的流程中使用这些属性，否则将提供运行时的错误处理来提醒我们相关扩展属性不支持。

---

#### 4.完善Vulkan实例结构体配置

到这里，我们Vulkan扩展层属性就已经准备完毕了，你是否还记得我们创建实例的结构体还有两个属性没有正确配置呢？那么接下来就是回到之前创建实例的函数方法中去完善实例结构体的配置。

**HelloTriangleApplication.cpp**

```cpp
void HelloTriangleApplication::CreateInstance()
{
    //上面代码保持不变

    vk::InstanceCreateInfo instanceCreateInfo = {
        instanceCreateInfo.flags                  = {},        //标志位
        instanceCreateInfo.pApplication           = &appInfo,  //应用程序实例
        instanceCreateInfo.enabledLayerCount      = static_cast<uint32_t>(requiredLayers.size()), //验证层
        instanceCreateInfo.ppEnabledLayerNames    = requiredLayers.data(), //验证层名称
        instanceCreateInfo.enabledExtensionCount  = static_cast<uint32_t>(requiredExtensions.size()),//扩展层
        instanceCreateInfo.ppEnabledExtensionNames = requiredExtensions.data(),  //扩展层名称
        instanceCreateInfo.pNext                  = nullptr    //结构体链链接对象
    }

    //下面代码保持不变
}
```

在之前我们创建的Vulkan实例结构体中，我们将把`enabledExtensionCount`属性和`ppEnabledExtensionNames`属性手动配置完整，我们分别给这两属性赋值为`requiredExtensions`容器的大小和具体数据，这等于告诉Vulkan我们有`requiredExtensions`容器大小个的扩展属性，以及`requiredExtensions`容器中这些扩展属性的具体名称。

### 添加成功

恭喜您，您已经完全增加了Vulkan的扩展支持，这仍然是非常重要的一步，从这里开始你就可以为不同的主机设备创建不同的适配扩展，这样做会使你的Vulkan程序适配更为广泛的设备类型，这也同样代表着你只需要编写一套代码，就能在多个设备上自由灵活的运行，完全不用为不同设备编写多套代码而担忧，这正是Vulkan最大的特点之一。
